## 1. 한 줄 결론

ohdo.ai 의 핵심 차별화는 **"AI 가 코드를 한 번 생성하고, 그 코드가 결정론적으로 N번 실행된다"** 는 컴파일타임 AI 모델이다. 이 포지션은 (a) 시각적 워크플로우의 UiPath/Zapier 와 (b) 매 실행마다 LLM 을 호출하는 Computer Use 류 양쪽에 대해 모두 **비용·신뢰성·디버깅 가능성** 측면의 우위를 가진다. 단, B2C 개인 개발자라는 좁은 초기 타깃과 Windows 우선이라는 플랫폼 제약, 1인 팀 실행 리스크가 가장 큰 변수다.

**시장 통과 가능성**: 중상. "오픈소스 + 코드 산출 + 진짜 데스크톱 제어" 세 축이 동시에 충족된 도구는 현재 부재 — 명확한 빈 슬롯이 존재. 다만 빈 슬롯이 큰지(수십만 개발자) 작은지(수천 마니아)는 Phase 3 의 MAU/Discord 데이터로 검증해야 한다.

## 2. 기존 RPA 와의 차별점 매트릭스

| 축 | UiPath / Automation Anywhere | Power Automate Desktop | Zapier / Make.com | n8n | **ohdo.ai** |
|---|---|---|---|---|---|
| 1차 타깃 | 대기업 IT | MS 생태계 사무직 | SMB 비개발자 | OSS 개발자 | **개인 개발자 → 팀** |
| 산출물 형태 | 시각 워크플로우(.xaml) | 시각 액션 | 시각 zap | 시각 노드 + JS | **순수 Python 코드** |
| 로컬 데스크톱 제어 | 강함 | 강함(Windows 한정) | 없음 | 없음 | **강함(Windows)** |
| 웹 자동화 | 강함 | 중 | 매우 강함 | 강함 | 중상(Selenium) |
| AI 통합 | 후행적 add-on | Copilot 부가 | 최근 add-on | 노드 형태 | **네이티브, 단계 대화형** |
| 라이선스 | 상용 | 상용(MS365 묶음) | 상용 | fair-code(BSL) | **AGPL-3.0 + 상업 SaaS** |
| 가격대 | $420+/seat·월 | $15+/사용자·월 | $20~ | self-host 무료 | **무료 OSS + 향후 $19/월** |
| Git/버전관리 | 별도 도구 | 약함 | 약함 | 일부 | **1급 시민(코드 산출)** |
| 오프라인 실행 | 가능(Robot) | 가능 | 불가 | 가능 | **가능(Agent)** |
| 비개발자 진입성 | 중 | 높음 | 매우 높음 | 중 | 중하(Python 친화 필요) |

### 2.1 어디가 비어 있나

- **UiPath/AA**: 엔터프라이즈 락인 + 시각 워크플로우 → "내 코드 가져가서 다른 곳에 쓴다" 가 불가. 가격이 1인 개발자 진입 불가능.
- **Power Automate**: MS 생태계 안에서만 강함. AI 코드 생성은 Copilot 한정 + 결과물 이식성 부족.
- **Zapier/Make**: SaaS API 끼워맞추기는 천재적이지만 **로컬 ERP·레거시 데스크톱 앱 못 건드림**. 이게 한국 중소기업의 RPA 수요 핵심.
- **n8n**: 개발자 친화에 가깝지만 자체 노드 그래프 → 코드 이식성 ohdo 보다 낮음. 데스크톱 자동화는 약함.
- **빈 슬롯**: "개발자가 사랑하고, Git 에 들어가고, AI 가 코드를 짜주고, 사내 ERP 도 누를 수 있는 도구". ohdo 가 노리는 위치다.

### 2.2 그 슬롯이 진짜 큰가 — 의심해야 할 점

- 개발자가 사랑하는 = 개발자가 직접 자동화 짠다 = "내가 그냥 Selenium/pywinauto 직접 쓰면 되는데?" 라는 자기충돌
- 반박: AI 가 짜주는 시간 절약 + 누적 컨텍스트 + 캡처/요소피커 + 세션 관리 + 향후 템플릿 마켓이 가치. 그러나 이 가치 제안은 **시연으로만 증명 가능** — 데모 영상 1편의 품질이 전환율을 좌우한다.

## 3. 비전(Vision) 기반 자동화와의 경쟁 분석

대상: Anthropic Computer Use, OpenAI Operator, Adept ACT-1, Browser Use, Skyvern, Runner H 등.

### 3.1 핵심 패러다임 차이

| 측면 | Vision/Agentic 자동화 | ohdo.ai (코드 생성형) |
|---|---|---|
| AI 호출 시점 | **매 실행마다** (스크린샷 → LLM → 액션) | **최초 1회** (대화로 코드 생성) |
| 결정론 | 비결정적 | 결정적(코드 고정 후) |
| 회당 비용 | $0.10~$2+ (스크린샷 토큰 + 추론) | 거의 0 (Python 실행) |
| 회당 지연 | 스텝당 2~10초 (LLM 왕복) | 인간 입력 속도 모방만 필요 |
| UI 변경 대응 | 강함(시각 일반화) | 약함(셀렉터 깨지면 수정 필요) |
| 디버깅 | 불투명("왜 클릭했지?") | 투명(코드 라인 단위) |
| 무인 야간 실행 | 비용·안정성 양쪽 부담 | 적합 |
| 개인정보 | 화면 → 외부 LLM 전송 | 코드만 외부, 실행은 로컬 |
| 학습 곡선 | 자연어만 알면 됨 | Python 친화도 필요 |

### 3.2 ohdo 가 우위인 영역 ("compile-time AI")

- **반복·고볼륨 작업**: 매일 자정 100건 ERP 입력 → 회당 $2 vs 거의 0. 1년이면 70만원 차이.
- **무인·스케줄 실행**: 비전은 비결정성으로 야간 실행 알람 폭탄. 코드는 같은 입력에 같은 출력.
- **감사·규제 환경**: 금융/의료 — "왜 이 클릭이 일어났나" 코드로 답변 가능. 비전은 답 못 함.
- **개인정보 민감**: 사내 ERP 화면 클라우드 LLM 전송 어려움. ohdo 는 코드 생성만 외부 → 코드 검토 후 실행은 로컬.
- **CI/CD 통합**: 코드 산출물이라 GitHub Actions 등에 그대로. 비전 에이전트는 별도 인프라.

### 3.3 비전 기반이 우위인 영역

- **일회성·탐색 작업**: "이 사이트 가서 정보 한 번만 긁어와" — 코드 짤 가치 없음
- **수시로 UI 가 바뀌는 대상**: 광고가 바뀌는 페이지, A/B 테스트 사이트 — 셀렉터 매번 깨짐
- **자연어만 가능한 사용자**: Python 모름, 코드 보기 싫음 — ohdo 의 진입장벽
- **모르는 앱·웹 처음 자동화**: 비전 에이전트는 스크린샷만 봐도 시작 가능

### 3.4 향후 5~10년 시나리오

**시나리오 A — 비전 에이전트가 모든 것을 흡수**
- 토큰 단가 100배 하락 + 추론 속도 10배 향상 + 결정성 개선
- 회당 $2 → $0.02, 스텝당 5초 → 0.5초 → 코드 생성형의 비용 우위 사라짐
- ohdo 의 가치 제안 약화. 대응 = 비전 도구의 코드 export 백엔드로 피벗.

**시나리오 B — 하이브리드가 표준** (가장 가능성 높다고 본다)
- 비전이 **1회차**(탐색·생성) 를 담당, 코드가 **N회차**(반복 실행) 를 담당
- ohdo 의 자연 진화 경로: AI 가 비전으로 화면 보면서 코드 생성 → 그 코드를 결정적으로 실행. 이미 `core/win_inspector.py` + `screen_capture.py` 가 이 구조의 절반.
- 추가로 "실행 중 비전 검증"(예: `assert vision.expects_button('확인')`) 같은 가드를 코드에 끼워넣으면 셀렉터 깨짐 리스크도 흡수 가능.

**시나리오 C — 두 시장 분리**
- 일회성·탐색 시장 → 비전 에이전트
- 운영·반복 시장 → 코드 생성형
- ohdo 가 후자의 OSS 표준이 되는 게 현실적 야망.

**권장**: ohdo 는 시나리오 B 를 기본으로 하되, **"AI 가 보면서 짠 코드"** 라는 혼합 포지셔닝을 선제적으로 마케팅. ROADMAP §5 우선순위 8번 "자연어 → 멀티스텝 자동 생성" 이 이 방향.

## 4. 경쟁력의 진짜 출처 — 5가지 가설

각 가설은 **검증 가능한 형태**로 적었다. 6개월 내 데이터로 참/거짓 판정 가능.

### H1. "코드 산출물" 자체가 차별화의 절반이다
- **근거**: 개발자는 자기 도구가 락인되는 것을 본능적으로 거부. n8n 의 부상이 이 본능의 증거.
- **검증**: GitHub Stars 1k+, Discord 가입자 200+ 까지의 **유입 키워드 분석**. "AI RPA Python", "AI Selenium" 류로 들어오는 비율 30%+ 면 가설 참.

### H2. "단계별 누적 + 수동 편집 보존" 이 경쟁자가 못 따라온다
- **근거**: prompt_builder.py 가 이미 이 일을 하고 있고, UiPath StudioX/Power Automate 에 같은 UX 가 부재. ChatGPT 코드 인터프리터에도 부재(스텝 단위 실행은 있어도 RPA 컨텍스트 누적 없음).
- **검증**: 사용자 인터뷰에서 "왜 ohdo 를 계속 쓰나" 답변에 "수정한 게 그대로 남아서" 가 상위 3안에 들면 참.

### H3. Windows 데스크톱 제어가 한국 시장에서 불가역적 진입로다
- **근거**: 한국 중소기업의 ERP·세무·은행 시스템은 여전히 Windows 데스크톱 클라이언트 비중 큼. Zapier/Make 가 못 들어가는 영역.
- **검증**: Phase 2 클로즈드 베타 100명 중 "사내 ERP 자동화" 사용 케이스가 30%+ 면 참. 만약 거의 전부 웹 자동화면 — 사실 Selenium 래퍼와 다를 바 없는 셈.

### H4. 오픈코어(AGPL-3.0) 가 신뢰 자산을 만든다
- **근거**: 데스크톱 RPA 는 보안 민감 (스크린 캡처, 키보드 후킹). 오픈소스 검증 가능성이 도입 결정에 영향.
- **검증**: 베타 사용자 인터뷰에서 "OSS 라서" 가 도입 이유 상위 5안에 들면 참. AGPL 의 viral 조항이 기업 도입을 막는 역효과도 측정해야 함.

### H5. 한국어 컨텍스트 + Gemini CLI 가 초기 우위를 만든다
- **근거**: 영어 중심 자동화 도구가 한글 입력·한국 사이트(네이버 스마트스토어, 쿠팡, 지마켓) 자동화에 약함. Gemini 의 한국어 코드 생성 품질이 Claude/GPT 대비 비용 효율적.
- **검증**: 초기 템플릿 라이브러리 Top 10 중 한국 서비스 자동화가 6개+ 면 참. (역설: 그러면 글로벌 확장에 별도 전략 필요.)

## 5. 약점과 리스크 (시장 관점)

ROADMAP §5 의 기술·비즈·법적 리스크와 별개로, 시장 침투 관점의 리스크.

### 5.1 진입장벽 양면성

- 강점: Python 친화 = 결과물 이식성, 신뢰. 약점: **타깃 시장 크기 자기제한**.
- 한국 개인 Python 개발자 모집단 추정: 30~50만. 그중 자동화 니즈 있는 자: 10~20%. TAM 5~10만.
- $19/월 × 5%(낙관적 침투율) = 월 $5만(=ROADMAP Phase 4 KPI). **국내만으로는 Phase 5 의 MRR $50k 가 어렵다 — 영어권 진출 필수**.

### 5.2 "Python 친화" 진입장벽이 마케팅 카피에서 모순을 만든다

- "자연어로 대화하는 RPA" — 비개발자에게도 어필
- "코드 산출물이 차별화" — 개발자에게 어필
- 이 둘이 동일 랜딩페이지에서 충돌. **이중 캠페인**(개발자용 + 파워유저용 분리 페이지) 이 필요.

### 5.3 Computer Use 의 가격 하락 곡선이 가설을 깰 수 있다

- 2026 현재 회당 $0.5~$2. 24개월 내 $0.05~$0.20 가능성 30%, $0.005 가능성 5%.
- $0.05 까지 떨어지면 ohdo 의 비용 우위는 **"고볼륨·무인 야간"** 케이스로 압축됨.
- 대응: 코드 산출물의 **이식성·감사·CI 통합** 같은 비-비용 차별화 축 강화.

### 5.4 1인 실행 리스크 (시장 측면)

- 6개월 후 공동 창업자 영입 못 하면 — 커뮤니티 응답 SLA 깨짐 → 신뢰 자산 손상 → OSS 성장 정체.
- B2C 오픈소스 도구의 95%는 Stars 1k 부근에서 멈춘다. ohdo 가 그 95% 가 안 될 결정적 이유는 아직 외부에서 안 보임. **"왜 이 도구가 5천 스타로 갈 것인가"** 의 한 문장이 명확하지 않다.

### 5.5 마켓플레이스 닭과 달걀

- ROADMAP §5 의 마켓플레이스가 살려면 템플릿 작성자 100+ + 구매자 1000+ 가 동시에 필요.
- 초기 견인책 없으면 빈 마켓이 신뢰를 깎는다. **운영 측이 직접 50~100개 시드 템플릿을 만들거나 유저 보상 프로그램**(템플릿 1개당 Pro 1년 무료 등) 필수.

## 6. 권장 시장 전략 (현 로드맵 보강)

### 6.1 단기 (Phase 0~1, 향후 6개월)

1. **데모 영상 3편** 우선 — 텍스트 설명 100배보다 30초 영상 1편이 강함:
   - "네이버 스마트스토어 주문 100건을 5초 만에 처리"
   - "엑셀에서 사내 ERP 로 자동 입력"
   - "AI 와 대화하면서 자동화 코드를 만드는 과정"
2. **공식 영문 README + 데모 사이트** — 영어권 동시 노출. ohdo.ai 도메인 영문 페이지 필수.
3. **벤치마크 글 1편** — "ohdo vs Computer Use vs Selenium 직접: 1000회 반복 시 비용·시간·안정성" 구체 숫자 비교. HN 게시 가능 컨텐츠.

### 6.2 중기 (Phase 2~3)

4. **하이브리드 포지셔닝 마케팅** — "AI 가 보면서 짠 결정적 코드" 캐치프레이즈. Vision 모델 통합을 R&D 가 아니라 **상품 차별화 1번**으로 승격.
5. **VS Code 확장** — 개발자 친화의 끝판. ohdo 세션을 IDE 안에서 편집·실행. n8n 도 못 한 영역.
6. **GitHub Action 러너** — `uses: ohdo/run-session@v1` 으로 CI 에서 실행. 개발자 유입 채널.

### 6.3 장기 (Phase 4~5)

7. **타깃 시장 재정의 시점** — Phase 4 진입 시 데이터 보고 결정:
   - Windows 데스크톱 자동화 비중이 50%+ → "Windows 자동화 표준 OSS" 포지션
   - 웹 자동화 비중이 70%+ → "AI 가 짠 Python 자동화 도구" 로 cross-platform 우선
8. **마켓플레이스 시드 작전** — Phase 5 진입 4개월 전부터 시드 템플릿 50개 자체 제작. 출시 첫날 빈 마켓 절대 금지.
9. **엔터프라이즈는 inbound 만** — 영업 인력 안 만듦. 한국 SI 대기업이 먼저 연락 오면 그때 대응. 그전엔 B2C 에 100% 집중.

## 8. 참고: 직접 비교군 한 줄 평

- **UiPath**: 적. 가격대·진입난이도·산출물 이식성 모두 ohdo 의 정반대. 직접 경쟁 안 함.
- **Power Automate Desktop**: MS 락인이 강해 ohdo 와 평행세계 운영.
- **Zapier / Make**: SaaS 워크플로우의 왕. ohdo 는 데스크톱 + 코드라는 다른 축.
- **n8n**: 가장 가까운 OSS 친척. 차별점은 (a) 데스크톱 (b) Python 산출물 (c) AI 단계 대화. 따라잡힐 위험은 OSS 답게 가장 큼.
- **Anthropic Computer Use / OpenAI Operator**: 비전 기반 동시대 신생주자. 같은 사용자 머릿속 예산을 두고 경쟁. 단기 보완재, 장기 잠재 대체재.
- **Browser Use / Skyvern**: 브라우저 한정 비전 자동화 OSS. 코드 산출 일부 지원. 웹 한정 영역에서 직접 경쟁.
- **Selenium / Playwright (스크립트 직접 작성)**: 가장 큰 "기존 대안". ohdo 의 진짜 경쟁자는 이것일 수도. 차별화 = AI 가 짜준다 + 캡처/요소피커 + 세션 관리 + 데스크톱.
