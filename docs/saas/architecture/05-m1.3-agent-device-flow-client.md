# 05. M1.3 — Agent 트레이 Sign In + Device Flow 클라이언트

- **상태**: 구현 착수 (2026-04-23)
- **이전 단계**: [04-m1.2-device-flow.md](04-m1.2-device-flow.md)
- **다음 단계**: M1.4 — 인증된 ping (Authorization: Bearer)

## 목표

M1.2 에서 Railway 에 완성해둔 Device Flow 엔드포인트를 **로컬 트레이 Agent 에서 실제로 호출** 해 로그인이 동작하게 만든다. 사용자 경험:

1. 트레이 아이콘 우클릭 → **Sign In** 클릭.
2. 기본 브라우저가 `https://ohdo-production.up.railway.app/link?code=ABCD-EFGH` 로 자동 오픈.
3. /link 페이지에서 이메일만 입력 → "기기가 연결되었습니다".
4. 트레이에서 풍선 알림 "Signed in as you@example.com" + 메뉴의 Sign In 이 비활성, Sign Out 이 활성화.
5. `%APPDATA%\ohdo\config.json` 에 `agent_token`, `agent_id`, `user_id` 저장.
6. 재기동 시 토큰 자동 로드 → Sign In 건너뜀.

M1.3 완료 조건:

- 트레이 메뉴에 Sign In / Sign Out 항목.
- `agent/auth.py` — `start_device_flow`, `poll_for_token`, 자격증명 save/load/clear.
- `config.json` 에 토큰 저장 (server_url 등 기존 키 보존).
- 기동 시 자격증명 로드. 없으면 로그만 WARN, 풍선 알림 1회.
- 로컬에서 Railway 대상 e2e 한 바퀴 통과.

M1.4 에서 이 토큰으로 `/healthz` 를 `Authorization: Bearer` 헤더로 호출하게 바꾼다 (또는 인증 전용 핑 엔드포인트 신설). 토큰을 **어디에 쓰는지** 까지는 M1.3 범위가 아님 — 저장·발급까지만.

## 클라이언트 흐름

```
[트레이: Sign In 클릭]
      │
      ▼
start_device_flow(server_url)
  │  POST /v0/agents/device_code
  │    body: {agent_name, hostname, platform, agent_version}
  │  응답: device_code, user_code, verification_uri_complete, expires_in, interval
  ▼
webbrowser.open(verification_uri_complete)
      │
      ▼
poll_for_token(server_url, device_code, interval, expires_in)
  │  while not expired:
  │    POST /v0/agents/device_token {device_code}
  │    - 200 → agent_token, agent_id, user_id  → return
  │    - 400 error=authorization_pending → sleep(interval) → 계속
  │    - 400 error=expired_token → raise DeviceFlowExpired
  │    - 400 error=access_denied → raise DeviceFlowDenied
  │    - 400 error=invalid_grant → raise DeviceFlowInvalid
  ▼
save_credentials(token, agent_id, user_id)
  │  config.json merge (기존 키 보존)
  ▼
[트레이: 풍선 알림 + 메뉴 토글]
```

## 파일 배치

```
agent/
├── agent_main.py          # 수정 — Sign In/Out 메뉴 + 기동 시 credentials 체크 + 알림
├── auth.py                # [신규] Device Flow 클라이언트 + credential I/O
└── requirements.txt        # 변경 없음 (httpx 이미 존재)
```

### `agent/auth.py` 인터페이스

```python
@dataclass
class DeviceCodeInfo:
    device_code: str
    user_code: str
    verification_uri: str
    verification_uri_complete: str
    expires_in: int
    interval: int

@dataclass
class Credentials:
    agent_token: str
    agent_id: str
    user_id: str
    server_url: str       # 발급받은 서버 URL (나중에 서버 변경 시 mismatch 감지용)
    signed_in_at: str     # ISO8601

class DeviceFlowError(RuntimeError): ...
class DeviceFlowPending(DeviceFlowError): ...   # 내부 전용 (폴링 루프용)
class DeviceFlowExpired(DeviceFlowError): ...
class DeviceFlowDenied(DeviceFlowError): ...
class DeviceFlowInvalid(DeviceFlowError): ...

def start_device_flow(server_url: str, *, agent_name: str | None,
                      hostname: str, platform: str,
                      agent_version: str) -> DeviceCodeInfo: ...

def poll_for_token(server_url: str, device_code: str, *,
                   interval: int, expires_in: int,
                   stop_event: threading.Event | None = None) -> Credentials: ...

def load_credentials() -> Credentials | None: ...
def save_credentials(creds: Credentials) -> None: ...
def clear_credentials() -> None: ...
```

`load`/`save`/`clear` 는 `config.json` 전체를 읽고 **auth 관련 키만 갱신/삭제** 한다. `server_url` 등 기존 키는 보존.

### `agent_main.py` 변경

- `Credentials` 상태를 `threading.Lock` 보호 하에 모듈 수준에 보관.
- 메뉴:
  - `Sign In` — `enabled=lambda _: not signed_in()`
  - `Sign Out` — `enabled=lambda _: signed_in()`
- `Sign In` 핸들러 → 별도 데몬 스레드에서 `start_device_flow` + `webbrowser.open` + `poll_for_token`. 완료 시 저장, 실패 시 로그.
- `Sign Out` 핸들러 → `clear_credentials()` + 로그.
- 메뉴 즉시 갱신을 위해 `icon.update_menu()` 사용.
- 기동 시 `load_credentials()` → 있으면 INFO 로그, 없으면 WARN + `icon.notify("Sign In required")`.
- pystray 의 `Icon.notify` 는 Windows 풍선 알림을 지원한다 (다른 OS 는 무시).

## 저장 스키마 (`%APPDATA%\ohdo\config.json`)

```jsonc
{
  "server_url": "https://ohdo-production.up.railway.app",   // 선택, 기존 M0 이후 유지
  "agent_token": "ag_...",    // M1.3 신규
  "agent_id": "uuid",         // M1.3 신규
  "user_id": "uuid",          // M1.3 신규
  "signed_in_at": "2026-04-23T10:12:00+00:00",  // M1.3 신규
  "token_server_url": "https://ohdo-production.up.railway.app"  // 토큰 발급받은 서버
}
```

- `server_url` 과 `token_server_url` 이 다르면 M1.4 에서 "토큰 무효 가능성" 경고를 낼 여지 (M1.3 에선 저장만).
- 파일 권한: `%APPDATA%` 는 이미 사용자 소유 폴더. 추가 ACL 없음. Windows 멀티유저 환경에서 관리자 권한으로 다른 사용자 APPDATA 를 읽지 않는 한 안전.

## 에러·UX 설계

| 상황 | 동작 |
|---|---|
| `authorization_pending` | 지정 `interval` 만큼 대기 후 재시도 |
| `expired_token` | 폴링 종료, 로그 `device flow expired`, 풍선 알림 "Sign In expired — try again" |
| `access_denied` | 폴링 종료, 로그 + 풍선 알림 |
| `invalid_grant` | 동일 |
| 네트워크 장애 | 3회 연속 실패 시 폴링 중단, 로그 + 풍선 알림 |
| 사용자가 중간에 Sign In 재클릭 | 이전 `stop_event` 세팅 → 새 흐름 시작 |

최대 폴링 시간은 `expires_in` (현재 기본 900초/15분) — 서버가 expired 로 돌려주므로 클라이언트는 추가 상한 없이 그 응답에 따른다.
