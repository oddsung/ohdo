## 목표

M3.1.1 의 쿠키 세션 API 를 **실제 브라우저로 사용** 가능하게 만드는 최소 프론트엔드. Next.js App Router 기반, Tailwind, 타자 세이프. 디자인 시스템은 M3.1.3+ 에서 shadcn 도입.

M3.1.2 완료 조건:

- `packages/web/` 신규. Next.js 14 + TypeScript + Tailwind CSS.
- 3 페이지:
  - `/` — 쿠키 확인 후 `/dashboard` 또는 `/sign-in` 으로 redirect (서버 컴포넌트).
  - `/sign-in` — 이메일 입력 → POST `/v0/auth/magic-link` → "링크 발송됨" 메시지.
  - `/dashboard` — 인증된 사용자의 `email` 표시 + Logout 버튼. (M3.1.3 에서 executions 리스트로 확장)
- Next.js `rewrites` 로 `/v0/*` + `/auth/verify` → 백엔드 proxy. CORS·쿠키 이슈 없음.
- 백엔드 `PUBLIC_BASE_URL` 을 프론트엔드 URL 로 세팅 → 매직링크 URL 이 `http://localhost:3000/auth/verify?token=...` 로 출력됨.
- 사용자가 로그에서 URL 복사 → 브라우저 붙여넣기 → 쿠키 Set → `/dashboard` 로 landing. 정상 동작.
- 코어 회귀 25/25 (프론트엔드만 추가, 백엔드 무변경).

### 왜 rewrite proxy 가 깔끔한가

두 가지 까다로운 것이 사라짐:
1. **CORS** — 프론트와 백엔드가 다른 origin 이면 `Access-Control-Allow-Origin` / `Access-Control-Allow-Credentials` 설정 필요. 쿠키 전송에 추가 헤더도 붙어 복잡.
2. **Set-Cookie 도메인** — 브라우저는 Next.js (`:3000`) 로 요청을 보냈다고 인식 → Set-Cookie 응답도 `:3000` 도메인에 attach.

rewrite 는 Next.js 서버가 백엔드로 HTTP proxy 하고 응답을 그대로 포워딩. 브라우저 관점에서 `:3000` 이 single origin.

## 주요 파일

### `next.config.ts` — rewrite proxy

```typescript
import type { NextConfig } from "next";

const backend = process.env.API_BASE_URL ?? "http://localhost:8000";

const config: NextConfig = {
  async rewrites() {
    return [
      { source: "/v0/:path*", destination: `${backend}/v0/:path*` },
      { source: "/auth/verify", destination: `${backend}/auth/verify` },
    ];
  },
};

export default config;
```

### `lib/api.ts`

```typescript
const base = "";  // same-origin; rewrites handle it

export async function apiFetch<T = unknown>(
  path: string,
  init?: RequestInit & { raw?: boolean },
): Promise<{ status: number; data: T | undefined }> {
  const res = await fetch(base + path, {
    ...init,
    credentials: "include",
    headers: {
      "content-type": "application/json",
      ...(init?.headers ?? {}),
    },
  });
  const data = res.status === 204 ? undefined : await res.json().catch(() => undefined);
  return { status: res.status, data: data as T | undefined };
}
```

### `lib/auth.ts`

서버 컴포넌트에서 쿠키 기반 user 조회.

```typescript
import { cookies } from "next/headers";

export async function getCurrentUser(): Promise<User | null> {
  const cookieStore = await cookies();
  const session = cookieStore.get("ohdo_session");
  if (!session) return null;
  const backend = process.env.API_BASE_URL ?? "http://localhost:8000";
  const res = await fetch(`${backend}/v0/users/me`, {
    headers: { cookie: `ohdo_session=${session.value}` },
    cache: "no-store",
  });
  if (!res.ok) return null;
  return (await res.json()) as User;
}
```

### `app/page.tsx` — 루트 redirect

```typescript
import { redirect } from "next/navigation";
import { getCurrentUser } from "@/lib/auth";

export default async function Home() {
  const user = await getCurrentUser();
  redirect(user ? "/dashboard" : "/sign-in");
}
```

### `app/sign-in/page.tsx`

클라이언트 컴포넌트. 이메일 폼 + `apiFetch("/v0/auth/magic-link", { method: "POST", body })`. 성공 시 "이메일로 발송된 링크를 클릭하세요" 안내.

### `app/dashboard/page.tsx`

서버 컴포넌트. `getCurrentUser()` 확인 → 없으면 `/sign-in` redirect. 있으면 "안녕 {email}" + Logout 버튼 (client component).

## 백엔드 환경변수

dev 시 백엔드에 `PUBLIC_BASE_URL=http://localhost:3000` 을 설정해 매직링크 URL 이 웹 주소로 출력되게. (uvicorn 실행 전 `$env:PUBLIC_BASE_URL="http://localhost:3000"`).

prod 배포 시 `PUBLIC_BASE_URL=https://app.ohdo.ai` 등 (Vercel 배포 확정 후).

## 검증 (수동 — 브라우저 필요)

1. 두 터미널:
   - Terminal A: `cd packages/backend; $env:PUBLIC_BASE_URL="http://localhost:3000"; .venv\Scripts\python.exe -m uvicorn app.main:app --port 8000 --log-level info`
   - Terminal B: `cd packages/web; npm run dev`
2. 브라우저: `http://localhost:3000` → 쿠키 없으므로 `/sign-in` 으로 redirect.
3. 이메일 입력 → Submit → "링크가 발송되었습니다" 메시지.
4. Terminal A 로그에서 `[MAGIC LINK] http://localhost:3000/auth/verify?token=...` 복사.
5. URL 을 브라우저에 붙여넣기 → 302 → `/dashboard` 로 이동 → "안녕 {email}" 표시. 쿠키 확인 (DevTools → Application → Cookies → `ohdo_session`).
6. Logout 클릭 → /sign-in 으로 redirect. 쿠키 제거 확인.
