# 18. M3.1.1 — Web Auth Backend (매직링크 + 세션 쿠키)

- **상태**: 구현 착수 (2026-04-24)
- **트리거**: M3.1 시작 — 브라우저 사용자 인증이 없음 (Agent 의 `Bearer ag_...` 는 기기용이라 웹 세션으로 부적합)
- **다음 단계**: M3.1.2 — Next.js scaffold + Sign-in 페이지

## 목표

브라우저에서 사용자가 **이메일로 로그인** → **httpOnly 세션 쿠키** 가 발급되어 이후 REST 호출이 자동 인증되는 최소 시스템을 백엔드에 추가한다. 실 이메일 발송은 M3.2+ 로 미루고 dev 는 로그 stub.

M3.1.1 완료 조건:

- 새 테이블 `user_sessions` + `magic_links` + Alembic `0006`.
- `POST /v0/auth/magic-link { email }` → 202 + 서버 로그에 `http://.../auth/verify?token=...` 출력 (stub).
- `GET /auth/verify?token=...` → 유효하면 user get-or-create + 세션 생성 + `Set-Cookie: ohdo_session=...; HttpOnly; SameSite=Lax` + 302 redirect.
- `POST /v0/auth/logout` → 세션 revoke + 쿠키 clear.
- `GET /v0/users/me` → 쿠키 기반 인증, 사용자 정보 반환.
- `current_user` dependency (cookie → UserSession → User lookup), `current_agent` 와 완전 별개.
- 로컬 e2e + Railway e2e + 코어 회귀 25/25.

## 설계 결정

| # | 항목 | 결정 |
|---|---|---|
| 1 | 세션 토큰 포맷 | `sess_<32byte base32 lowercase>` (`ag_` 와 유사한 prefix) |
| 2 | 쿠키 속성 | `httpOnly; SameSite=Lax; Path=/; Secure` (dev 에선 http 허용 위해 `Secure` off) |
| 3 | 세션 만료 | 30일 fixed (rolling 은 M3.1.3+ 에서) |
| 4 | 매직링크 TTL | 15분. 사용 후 `consumed_at` 세팅 → 재사용 차단 |
| 5 | 이메일 발송 | **dev stub**: 서버 INFO 로그에 URL 출력. 실 SMTP 는 M3.2 (결제) 함께 |
| 6 | 이메일 normalization | `.strip().lower()` |
| 7 | 매직링크 요청 rate limit | M3.1.1 에선 없음. 남용 방어는 나중에 |

| 9 | verify 엔드포인트 경로 | `/auth/verify` (`/v0/` prefix 없음 — 사용자가 브라우저로 직접 클릭하는 URL) |

## 인증 흐름

```
1. 브라우저 → POST /v0/auth/magic-link { "email": "a@b.com" }
2. 서버: random 32B → token_hash 저장, expires_at = now+15min
   dev 로그: "[MAGIC LINK] http://localhost:8000/auth/verify?token=<raw>"
   응답 202 { "email": "a@b.com", "expires_in": 900 }

3. 사용자 (로그에서 URL 복사 or 이메일 클릭) → GET /auth/verify?token=<raw>
4. 서버:
   - magic_links 조회 (token_hash, not consumed, not expired)
   - email 로 users get-or-create
   - 새 user_sessions row 생성 (token=random 32B, expires_at=now+30d)
   - magic_links.consumed_at = now
   - Set-Cookie: ohdo_session=sess_<raw>; HttpOnly; SameSite=Lax; Path=/
   - 302 Location: /  (dashboard 으로)

5. 브라우저 → GET /v0/users/me  (쿠키 자동 첨부)
6. 서버: current_user dep → user_sessions 조회 → last_seen_at 갱신 → User 반환
   응답 200 { "id": "...", "email": "a@b.com", "created_at": "..." }

7. (옵션) POST /v0/auth/logout (쿠키 필요)
   → user_sessions.revoked_at = now, Set-Cookie: ohdo_session=; Max-Age=0
   → 204
```

## API 스펙

### `POST /v0/auth/magic-link`

요청:
```json
{ "email": "user@example.com" }
```
응답 202:
```json
{ "email": "user@example.com", "expires_in": 900 }
```

Validation: 이메일은 `@` 포함 필수. 정상이면 **같은 이메일로 반복 요청해도 매번 새 토큰 발급** (이전 토큰은 만료될 때까지 유효).

에러:
- 400 `invalid_email` — `@` 없거나 빈 문자열

### `GET /auth/verify?token=<raw>`

성공:
- `Set-Cookie: ohdo_session=sess_<raw>; HttpOnly; SameSite=Lax; Path=/`
- `Location: /`
- 302

실패:
- 400 `invalid_or_expired_token` — hash 불일치 / 만료 / 이미 consumed
- 400 `missing_token` — 쿼리 파라미터 없음

### `POST /v0/auth/logout`

요청: 쿠키 필요 (body 없음).

응답 204 + `Set-Cookie: ohdo_session=; Max-Age=0; Path=/`.

쿠키 없음 → 그냥 204 (idempotent).

### `GET /v0/users/me`

응답 200:
```json
{
  "id": "uuid",
  "email": "a@b.com",
  "created_at": "ISO-8601"
}
```

에러 401: `not_authenticated` (쿠키 없음 / 세션 만료 / revoked).

## `current_user` dependency

```python
async def current_user(
    request: Request,
    session: AsyncSession = Depends(get_session),
) -> User:
    raw = request.cookies.get(SESSION_COOKIE_NAME)
    if not raw or not raw.startswith(SESSION_TOKEN_PREFIX):
        raise HTTPException(401, detail={"error": "not_authenticated"})
    token_hash = hash_token(raw)
    stmt = select(UserSession, User).join(User, User.id == UserSession.user_id).where(
        UserSession.token_hash == token_hash,
    )
    row = (await session.execute(stmt)).first()
    if row is None:
        raise HTTPException(401, detail={"error": "not_authenticated"})
    us, user = row
    now = datetime.now(timezone.utc)
    if us.revoked_at is not None or us.expires_at <= now:
        raise HTTPException(401, detail={"error": "session_expired"})
    us.last_seen_at = now
    await session.commit()
    return user
```

## 토큰 생성·검증 헬퍼

```python
# app/auth.py 확장
SESSION_TOKEN_PREFIX = "sess_"
MAGIC_LINK_TOKEN_LEN = 32  # bytes

def generate_session_token() -> str:
    return SESSION_TOKEN_PREFIX + secrets.token_urlsafe(32)

def generate_magic_token() -> str:
    return secrets.token_urlsafe(32)
```

hash_token 은 기존 로직 재사용 (sha256 hex).

## 검증

### 로컬 e2e

1. `POST /v0/auth/magic-link { email: "test@ex.com" }` → 202
2. 서버 로그에서 `token=<raw>` 추출
3. `GET /auth/verify?token=<raw>` → 302, Set-Cookie
4. 쿠키 들고 `GET /v0/users/me` → 200, email 일치
5. DB 확인: users, user_sessions, magic_links(consumed_at) 각 1 row
6. 만료된 매직링크 재사용 → 400
7. 잘못된 토큰 → 400
8. 쿠키 없이 `GET /v0/users/me` → 401
9. `POST /v0/auth/logout` (쿠키) → 204
10. 이후 `GET /v0/users/me` (같은 쿠키) → 401 `session_expired`
