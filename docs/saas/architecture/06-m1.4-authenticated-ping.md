# 06. M1.4 — Authenticated Ping (Bearer 토큰 경로)

- **상태**: 구현 착수 (2026-04-23)
- **이전 단계**: [05-m1.3-agent-device-flow-client.md](05-m1.3-agent-device-flow-client.md)
- **다음 단계**: M1.5 — WebSocket `/v0/agent` + `agent.hello`

## 목표

M1.3 에서 Agent 가 발급받은 `agent_token` 을 **실제 요청에 사용** 하는 최소 구간을 완성한다. 토큰이 유효한지 왕복으로 확인하고, 만료·revoke 시 자동으로 로그아웃 상태로 복귀하는 경로를 확보한다.

M1.4 완료 조건:

- 서버에 Bearer 인증 dependency (`app/dependencies.py`) — Authorization 헤더를 파싱해 `Agent` 행을 반환, 실패 시 401 (RFC 6750 스타일).
- 서버에 `GET /v0/agents/me` 엔드포인트 — Bearer 전용. 자기 정보 반환 + `last_seen_at = now()` 업데이트.
- Agent 의 `HealthPinger` 가 **로그인 상태면** `/v0/agents/me` 로, **아니면** 기존 `/healthz` 로 ping (gradual rollout).
- 401 응답 수신 시 Agent 는 자동으로 `clear_credentials()` + 풍선 알림 + 이후 anonymous ping 으로 폴백.
- Railway 대상 e2e: 토큰으로 `/v0/agents/me` 200, agents 테이블의 `last_seen_at` 업데이트 확인.

M1.5 에서 이 토큰을 WebSocket 핸드셰이크에 쓰게 되므로, M1.4 의 역할은 "HTTP 레이어에서 토큰이 제대로 흐르는지 증명" 하는 것.

## 서버 설계

### 인증 의존성 (`app/dependencies.py`)

```python
async def current_agent(
    request: Request,
    session: AsyncSession = Depends(get_session),
) -> Agent:
    token = _extract_bearer_token(request)  # Authorization: Bearer ag_...
    if token is None or not token.startswith(AGENT_TOKEN_PREFIX):
        raise _unauthorized("missing_or_malformed_token")

    token_h = hash_token(token)
    result = await session.execute(
        select(Agent).where(Agent.token_hash == token_h)
    )
    agent = result.scalar_one_or_none()
    if agent is None:
        raise _unauthorized("invalid_token")
    if agent.revoked_at is not None:
        raise _unauthorized("token_revoked")

    return agent
```

- `_unauthorized(code)` → `HTTPException(401, detail={"error": code})` + `WWW-Authenticate: Bearer error="invalid_token"` 헤더. RFC 6750 §3.1 참고.
- `ag_` prefix 누락 시 DB 조회 없이 즉시 401 (타이밍 공격 방어는 과도 — 같은 latency 를 주진 않지만 prefix 필터링 자체는 유용).
- 기존 `app/auth.py` 의 `AGENT_TOKEN_PREFIX` 와 `hash_token` 재사용.

### 엔드포인트 `GET /v0/agents/me`

```python
@router.get("/me", response_model=AgentMeResponse)
async def get_me(
    agent: Agent = Depends(current_agent),
    session: AsyncSession = Depends(get_session),
) -> AgentMeResponse:
    agent.last_seen_at = datetime.now(timezone.utc)
    await session.commit()
    return AgentMeResponse(
        agent_id=str(agent.id),
        user_id=str(agent.user_id),
        name=agent.name,
        hostname=agent.hostname,
        platform=agent.platform,
        agent_version=agent.agent_version,
        last_seen_at=agent.last_seen_at,
    )
```

- 라우터 prefix `/v0/agents` 이므로 최종 경로는 `/v0/agents/me`.
- `last_seen_at` 을 매 요청마다 업데이트 (dashboard/ops 관점에서 "가장 최근 ping" 이 곧 "기기 활성 상태").
- 민감 데이터는 반환하지 않음 (token_hash 등 제외).

### 라우터 파일 분리

기존 `app/routers/device_flow.py` 는 익명 경로(device_code/device_token) 전용. 새 Bearer 인증 경로는 **같은 prefix `/v0/agents`** 를 공유하지만 파일은 **분리** 한다:

- `app/routers/agents.py` [신규] — `/v0/agents/me` 포함. 향후 `/v0/agents/heartbeat`, `/v0/agents/revoke` 등도 여기로.
- `app/main.py` 에 라우터 추가.

### 401 응답 형식

```
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer error="invalid_token"
Content-Type: application/json

{"detail": {"error": "invalid_token"}}
```

Agent 쪽 파서는 M1.3 `auth.py` 의 `_parse_rfc8628_error` 가 이 형식을 이미 처리한다 (device_flow 와 동일한 형태).

## Agent 설계

### `HealthPinger` 확장

현재 `HealthPinger` 는 `server_url` 과 `interval` 만 받는다. M1.4 는 `AuthState` 참조와 인증 실패 콜백을 추가로 받아 **tick 마다 현재 credentials 를 조회** 해서 경로를 결정한다:

```python
class HealthPinger:
    def __init__(
        self,
        server_url: str,
        interval_seconds: int,
        auth_state: AuthState,
        on_unauthorized: Callable[[], None] | None = None,
    ) -> None: ...

    def _ping_once(self) -> None:
        creds = self.auth_state.credentials
        if creds is not None and creds.token_server_url.rstrip("/") == self.server_url.rstrip("/"):
            self._ping_authenticated(creds.agent_token)
        else:
            self._ping_anonymous()
```

- `token_server_url` 비교로 **다른 서버에서 발급받은 토큰이 섞일 위험** 을 방어.
- 401 수신 시 `on_unauthorized()` 호출 → `AuthState.handle_unauthorized()` → `clear_credentials()` + 알림 + 메뉴 갱신. 이후 ticks 는 자동으로 anonymous 경로로 폴백.
- 기타 상태 (비 401 에러, 네트워크 실패) 는 기존 로직 그대로.

### 메뉴·UX 변경

- 별도 메뉴 항목 추가 없음. Sign Out 후에도 ping 은 계속됨 (anonymous `/healthz`).
- 401 감지 시 풍선 알림 "Session expired — please Sign In again" + 로그 WARN.

## 검증 계획

### 로컬 (SQLite)

1. `uvicorn app.main:app --reload --port 8000` 기동.
2. 새 agent 발급 (기존 Device Flow 경로 재사용).
3. `curl -H "Authorization: Bearer ag_..." http://localhost:8000/v0/agents/me` → 200 + JSON.
4. 동일 요청 10초 간격 2회 → `last_seen_at` 두 번째 응답이 첫 번째보다 새로움.
5. 잘못된 토큰 → 401 `{"detail":{"error":"invalid_token"}}`.
6. prefix 없는 토큰 → 401 `missing_or_malformed_token`.
7. 직접 `UPDATE agents SET revoked_at = now()` 후 재요청 → 401 `token_revoked`.

### Railway (production)

1. 기존 `ag_8JA...` (M1.3 에서 사용자 기기에 저장된 토큰) 그대로 사용.
2. `GET /v0/agents/me` 200 확인.
3. 같은 토큰으로 두 번째 요청, Railway Postgres 에서 `SELECT last_seen_at FROM agents WHERE id='ea2be8bf...'` 확인.
4. 로컬에서 agent 기동 → 30초 주기 ping 로그에 `ping ok: /v0/agents/me status=200` 이 찍히는지.
5. 임시로 revoke 처리 (DB 직접 SQL) → agent 로그에 401 + `signed out` + `Session expired` 알림 순차 발생.

## 보안 메모

- 401 응답에 구체적 이유 (`invalid_token` vs `token_revoked`) 를 노출. 공격자에게 정보를 조금 주지만, 운영상 디버깅 이득이 더 크고 토큰 자체가 opaque 라 브루트 포스 여지 없음.
- `Authorization` 헤더는 HTTPS 위에서만 의미. Railway 는 TLS 자동, 로컬은 HTTP. 로컬 HTTP 에서 토큰을 사용하는 건 개발자 본인의 PC 에서만이므로 수용.
- `last_seen_at` 업데이트는 매 요청. 수천 대 동시 ping 시 쓰기 부하 문제가 될 수 있으나 M1.4 범위에선 무시. M2+ 에서 "60초 내 변경 없으면 skip" 최적화 여지.

## M1.4 범위 밖 (의도적 deferred)

- Token rotation / revoke 대시보드 — M3+.
- JWT / 만료 클레임 기반 토큰 — 현재 opaque + DB 조회가 M1/M2 규모에 충분.
- Rate limiting (per-agent, per-IP) — M2+ (nginx/FastAPI middleware).
- `/v0/agents/heartbeat` 등 별도 keep-alive 경로 — `/me` 하나로 갈음 (M1.5 의 WebSocket 이 실질 keep-alive 를 담당할 예정).
