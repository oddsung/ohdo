# 15. M2.8 — Embedded Python 동반으로 `CodeSandbox` 재귀 실행 제거

- **상태**: 구현 착수 (2026-04-24)
- **이전 단계**: [14-m2.7-agent-bundle-core.md](14-m2.7-agent-bundle-core.md)
- **트리거**: M2.7 실기 검증에서 확인된 "bundled `ohdo-agent.exe` 가 `sys.executable` 이 되어 RPA 코드 실행 시 자기 자신을 재귀 spawn" 문제

## 배경 — 왜 꼭 필요한가

M2.7 설치본 실기에서:

```
09:42:50 POST /v0/executions exec_be33... (status=queued)
09:42:50 agent 재시작 로그 발생 ← CodeSandbox 가 sys.executable 을 subprocess.Popen 으로 호출 → 자식 ohdo-agent.exe 가 트레이 앱으로 뜸
09:42:50 자식이 WS 연결 → 서버 registry 가 자식 WS 로 덮어써짐
09:43:40 execution.cancel 도착 → registry 의 자식 WS 로 push
09:43:40 자식은 해당 execution 을 모름 → "cancel for unknown/finished execution"
09:43:50 부모 엔진은 cancel 을 받지 못한 채 60초 timeout → failed
```

부모는 계속 돌지만 registry 하이재킹으로 어떤 WS 푸시도 부모에 닿지 못함. 실 Python 코드 실행도 불가능.

## 목표

Agent 설치본이 RPA 코드를 실제로 **실행 가능** 하게 만든다. `sys.executable` 대신 별도 `python.exe` 를 동반·사용.

M2.8 완료 조건:

- 설치본에 **Python 3.12 임베디드 패키지** 가 동반 설치됨.
- `CodeSandbox` 가 `sys.executable` 이 아니라 동반된 `python.exe` 를 사용하도록 `runner.py` 에서 명시적 주입.
- 설치본 실기: 단순 스텝 (`print('hello')`) 이 `status=completed` 로 통과.
- 설치본 실기: mid-run cancel 이 `status=cancelled` 로 통과 (registry 하이재킹 해소 확인).
- 번들 용량 +15 MB 허용 (embeddable zip 자체가 ~11 MB).
- 빌드 smoke + 코어 회귀 25/25.

## 구현

### 1) Fetch 스크립트 — `agent/scripts/fetch-embedded-python.ps1`

```powershell
# Download Windows embeddable Python 3.12.x and extract to agent/vendor/python/
$ErrorActionPreference = "Stop"
$VER = "3.12.7"   # 정기 업데이트. stable 3.12.
$URL = "https://www.python.org/ftp/python/$VER/python-$VER-embed-amd64.zip"
$VENDOR = Join-Path $PSScriptRoot ".." "vendor"
$TARGET = Join-Path $VENDOR "python"
$ZIP = Join-Path $VENDOR "python-embed.zip"

if (Test-Path $TARGET) {
    Write-Host "Already extracted: $TARGET"; exit 0
}

New-Item -ItemType Directory -Force -Path $VENDOR | Out-Null
Write-Host "Downloading $URL"
Invoke-WebRequest -Uri $URL -OutFile $ZIP
Write-Host "Extracting to $TARGET"
Expand-Archive -LiteralPath $ZIP -DestinationPath $TARGET
Remove-Item $ZIP
Write-Host "Done. Python.exe: $TARGET\python.exe"
```

### 2) `.gitignore` 추가

```
agent/vendor/
```

### 3) `build.spec` 수정

```python
a = Analysis(
    ...
    datas=[
        (str(AGENT_ROOT / "vendor" / "python"), "python"),
    ],
    ...
)
```

PyInstaller 는 이걸 번들의 `_internal/python/` 에 복사한다.

### 4) `agent/runner.py` 에 `_resolve_python_exe()` 추가

```python
def _resolve_python_exe() -> str:
    """번들 환경에선 동반된 embedded python, dev 에선 sys.executable."""
    mei = getattr(sys, "_MEIPASS", None)
    if mei:
        cand = Path(mei) / "python" / "python.exe"
        if cand.is_file():
            return str(cand)
    return sys.executable
```

`_run_execution_inner` 에서:

```python
from core.workflow_engine import WorkflowEngine, CodeSandbox

...
sandbox = CodeSandbox(python_exe=_resolve_python_exe())
engine = WorkflowEngine(
    sandbox=sandbox,
    step_delay_ms=0,
    screenshot_on_error=True,
    visual_feedback_enabled=False,
)
```

### 5) 버전 bump

- `agent/__init__.py`: `0.1.0 → 0.2.0`
- `agent/agent_main.py`: `__version__ = "0.2.0"`
- `installer/ohdo-agent.iss`: `MyAppVersion "0.2.0"`

## 알려진 제약 (M2.9+ 로 미룸)

1. **Stdlib 한정**. user code 에서 `import pywinauto` 등 하면 ImportError. 실제 RPA 시나리오는 제한적 — M2.9 에서 ensurepip + per-session venv 또는 번들 내 `site-packages/` 확장 검토.
2. **python 실행 격리 부재**. embedded python 이 user code 를 전체 파일시스템 권한으로 실행. 향후 샌드박스 (WinPty + AppContainer) 고려.
3. **Startup cost**. python.exe 콜드 스타트 ~100ms (경미).

## 검증

### 빌드

1. `powershell -File agent/scripts/fetch-embedded-python.ps1` → `agent/vendor/python/python.exe` 존재 확인.
2. `cd agent && pyinstaller build.spec --clean --noconfirm` → 빌드 성공. `dist/ohdo-agent/_internal/python/python.exe` 존재.
3. `dist/ohdo-agent/` 총 용량 이전 대비 +10~15 MB.

### Smoke (자동)

개발 PC 에서 번들 exe 기동 → 로그에 `version=0.2.0` + `ping ok (anonymous)`. **추가로** embedded python 이 존재하는지 확인:

```powershell
& "dist/ohdo-agent/_internal/python/python.exe" -c "import sys; print(sys.version)"
```

→ 3.12.x 출력 기대.

### 설치본 실기 (사용자)

M2.7 과 동일 프로토콜이지만 이번엔:
1. `ohdo-agent-setup-0.2.0.exe` 설치
2. Sign In
3. POST /v0/executions `print('hello from installer 0.2.0')`
4. **status=completed** 기대 (failed 타임아웃 아님)
5. mid-run cancel 시나리오 → **status=cancelled** 기대
