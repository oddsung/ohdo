M2.6 완료 조건:

- `GET /v0/captures/{capture_id}` — 바이너리 다운로드, user_id 스코프.

## 테이블 설계 — `execution_captures`

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| `id` | `Uuid` | PK | API 의 capture_id |
| `execution_id` | `Text` | FK → executions.execution_id ON DELETE CASCADE, indexed | 소속 execution |
| `step_id` | `Integer` | nullable | 실패 스텝 번호 (없으면 null) |
| `kind` | `Text` | not null, default `'error_screenshot'` | 확장 대비 (사용자 캡처 등) |
| `storage_key` | `Text` | not null | 스토리지 내부 키 (로컬 파일시스템 상대 경로) |
| `content_type` | `Text` | not null | MIME |
| `size_bytes` | `Integer` | not null | 원본 크기 |
| `created_at` | `DateTime(tz)` | not null, server default now() | |

### 인덱스

- `execution_captures_execution_id_idx` — 조회 hot path.

### storage_key 스키마

- 로컬: `"{execution_id}/{capture_id}.{ext}"` (base 는 `CAPTURE_ROOT` 환경 변수 or 기본 `packages/backend/data/captures`).
- 추후 S3: 같은 구조이지만 `CAPTURE_ROOT` 가 bucket URL 로 바뀜 + presign. 스키마 변경 불필요.

## API

### `POST /v0/executions/{execution_id}/captures`

- **Auth**: Bearer agent (current_agent).
- **권한**: execution.user_id == agent.user_id (404 otherwise).
- **Body**: multipart form
  - `file`: binary (required)
  - `step_id`: int (optional, form)
  - `kind`: str (optional, default `"error_screenshot"`)
- **Content-Type** 허용: `image/png`, `image/jpeg`
- **크기 제한**: 10 MB. 초과 시 413.
- **응답 201**: `{capture_id, execution_id, step_id, kind, content_type, size_bytes, created_at}`

### `GET /v0/executions/{execution_id}/captures`

- **Auth**: Bearer agent
- **권한**: user_id 스코프
- **응답 200**: `{items: [{capture_id, step_id, kind, content_type, size_bytes, created_at}, ...]}` (최신순, limit 100 default)

### `GET /v0/captures/{capture_id}`

- **Auth**: Bearer agent
- **권한**: capture → execution.user_id == agent.user_id (join). 다른 user 면 404.
- **응답 200**: 바이너리 스트림, Content-Type 은 DB 의 `content_type`.

## 서버 구현

### 파일 스토리지 레이아웃

```
packages/backend/
└── data/
    └── captures/
        └── {execution_id}/
            └── {capture_id}.{ext}
```

- 업로드 시 `(capture_root / execution_id).mkdir(parents=True, exist_ok=True)` 호출.
- 파일명은 `{capture_id}.{ext}` (ext 는 content_type 에서 매핑: image/png → png, image/jpeg → jpg).

### routers/captures.py

두 라우터 (prefix 다름):

```python
exec_captures = APIRouter(prefix="/v0/executions", tags=["captures"])
cap_router = APIRouter(prefix="/v0/captures", tags=["captures"])
```

### 보안

- path traversal 방어: execution_id 는 regex 검증 (`^exec_[a-f0-9]{32}$`), capture_id 는 uuid4 검증.
- 파일 저장 전 `Path.resolve()` 로 capture_root 하위인지 재검증.

## 에이전트 구현

### runner.py 변경

1. `WorkflowEngine(screenshot_on_error=True)` 로 복귀 (M2.3 에서 False 였음). visual_feedback_enabled 는 계속 False.
2. `ExecutionRunner` 에 `set_http_context(server_url, auth_state)` 추가.

### `_upload_capture` 구현 (httpx)

```python
import httpx

def _upload_capture(self, execution_id, step_id, path):
    if not (self._server_url and self._auth_state and self._auth_state.credentials):
        return
    token = self._auth_state.credentials.agent_token
    try:
        with open(path, "rb") as f:
            content = f.read()
        url = f"{self._server_url.rstrip('/')}/v0/executions/{execution_id}/captures"
        resp = httpx.post(
            url,
            headers={"Authorization": f"Bearer {token}"},
            files={"file": (os.path.basename(path), content, "image/png")},
            data={"step_id": str(step_id), "kind": "error_screenshot"},
            timeout=20.0,
        )
        if resp.status_code == 201:
            cid = resp.json().get("capture_id")
            logger.info("capture uploaded: step_id=%s capture_id=%s", step_id, cid)
        else:
            logger.warning("capture upload non-201: %s %s", resp.status_code, resp.text[:200])
    except Exception:
        logger.exception("capture upload failed")
```

## 검증

### 로컬 e2e

실제 `mss` 없이도 업로드 파이프라인을 검증하기 위해 `WorkflowEngine._capture_error_screen` 을 monkey-patch 로 stub:

```python
def fake_capture(self, session_id, step_id):
    p = tempfile.mktemp(suffix=".png")
    # minimal PNG header + 바이트 chunk
    with open(p, "wb") as f:
        f.write(b"\x89PNG\r\n\x1a\n" + b"\x00" * 100)
    return p
WorkflowEngine._capture_error_screen = fake_capture
```

시나리오:
- S1: 실패 스텝 하나 → 자동 업로드 → `GET .../captures` 에 1 row → `GET /v0/captures/{id}` 로 바이트 다운로드 성공.
- S2: 성공 스텝만 → 캡처 0 row.
- S3: 다른 user 의 capture_id 다운로드 → 404.
- S4: unauth → 401.
- S5: 다른 user 의 execution 의 captures 리스트 → 404.
- S6: 잘못된 content-type 업로드 → 415.
- S7: 10 MB 초과 업로드 → 413.

### Railway e2e

monkey-patch 한 동일 stub 로 wss 대상 S1 (업로드 + 다운로드 round-trip) 재확인.

**참고**: Railway 컨테이너 파일시스템은 ephemeral — 재배포 시 캡처 소실. **운영 전 S3/R2 교체 필수** (본 CHANGELOG 에 기록).
