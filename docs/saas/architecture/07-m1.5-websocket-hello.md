# 07. M1.5 — WebSocket `/v0/agent` + `agent.hello` 핸드셰이크

- **상태**: 구현 착수 (2026-04-23)
- **이전 단계**: [06-m1.4-authenticated-ping.md](06-m1.4-authenticated-ping.md)
- **다음 단계**: M2.0 — 실제 RPA 실행 이벤트 (`execution.start`/`execution.log`/`execution.result`)

## 목표

[프로토콜 v0 초안](../protocols/AGENT_PROTOCOL.md) 의 핸드셰이크 구간만을 실제 코드로 증명. 실행 메시지는 M2 로 넘긴다.

M1.5 완료 조건:

- 서버에 `WS /v0/agent` 엔드포인트. Bearer 헤더 인증, 인증 실패 시 WS close code 로 구분 가능한 종료.
- 연결 직후 서버가 **server.hello** 를 먼저 보낸다 (agent_id / user_id / server_version).
- Agent 가 이를 받고 `agent.hello` 로 답장한다 (hostname / platform / agent_version).
- 서버는 `agent.hello` 수신 시 `last_seen_at = now()` 갱신.
- Agent 는 별도 스레드에서 WS 연결을 유지. 끊기면 지수 백오프로 재연결. 401/403 close code 수신 시 credentials 정리 후 재연결 중단 (M1.4 의 `AuthState.handle_unauthorized` 재사용).
- 기존 `HealthPinger` 와 공존 — M1.5 범위 내에서는 둘 다 돈다.
- Railway 대상 `wss://` 연결 확인.

실행 이벤트(`execution.*`) 는 M2 에서 붙인다. M1.5 는 "파이프가 뚫려 있고 인증·재연결이 동작한다" 를 증명.

## 프로토콜 세부

### 연결 URL

| 환경 | URL |
|---|---|
| 로컬 | `ws://127.0.0.1:8000/v0/agent` |
| Railway | `wss://ohdo-production.up.railway.app/v0/agent` |

스킴은 HTTP/HTTPS 에 대응 (`http` → `ws`, `https` → `wss`).

### 인증

**Authorization 헤더** 를 1순위로 쓴다:

```
Authorization: Bearer ag_<opaque>
```

- Python `websockets` 클라이언트는 `additional_headers=[("Authorization", f"Bearer {token}")]` 로 손쉽게 전달 가능.
- 브라우저 WebSocket API 는 커스텀 헤더 설정 불가 — 향후 웹 UI 가 붙을 때 subprotocol (`Sec-WebSocket-Protocol: bearer, ag_xxx`) 지원을 추가 검토. M1.5 범위 밖.

### Close code 규약

정상/비정상 종료를 표준 + 애플리케이션 구역(4000-4999) 섞어서 구분:

| Code | 의미 | 서버 → 클라이언트 트리거 |
|---|---|---|
| 1000 | 정상 종료 | 양쪽 어느 쪽이든 |
| 1001 | going away (프로세스 종료) | 양쪽 |
| 4401 | `missing_token` / `malformed_token` / `invalid_token` | 서버 |
| 4403 | `token_revoked` | 서버 |
| 4400 | 프로토콜 위반 (예: 비 JSON 프레임, 잘못된 `type`) | 서버 |

- 클라이언트는 `4401`/`4403` 수신 시 `AuthState.handle_unauthorized` 호출 (credentials 제거 + 풍선 알림). 이후 tick 에서 ping/WS 재시도는 자연스럽게 anonymous 로 내려가거나 중단.
- `4400` 은 로그만 남기고 재연결은 시도 (버그 수정 + 재배포 후 정상 동작 기대).

### 메시지 프레임

프로토콜 v0 가 정한 envelope 을 그대로 사용:

```jsonc
{
  "v": 0,
  "type": "server.hello" | "agent.hello",
  "id": "<uuid4>",
  "ts": "<ISO-8601 UTC>",
  "payload": { ... }
}
```

#### `server.hello` (Server → Client, 연결 직후 1회)

```json
{
  "v": 0,
  "type": "server.hello",
  "id": "<uuid4>",
  "ts": "2026-04-23T06:40:00Z",
  "payload": {
    "server_version": "0.0.1",
    "agent_id": "<uuid>",
    "user_id": "<uuid>",
    "heartbeat_seconds": 20
  }
}
```

- `agent_id`/`user_id` 는 Bearer 로 식별된 것. 클라이언트가 로컬 config 와 비교해 **서버가 인식한 agent 가 내 것이 맞는지** 확인할 수 있다.
- `heartbeat_seconds` 는 향후 애플리케이션 레이어 keep-alive 주기를 서버가 지시할 여지. M1.5 는 이 값을 수신만 하고 사용은 안 함 (WebSocket protocol-level ping/pong 에 맡김).

#### `agent.hello` (Client → Server, `server.hello` 에 대한 응답 1회)

```json
{
  "v": 0,
  "type": "agent.hello",
  "id": "<uuid4>",
  "ts": "2026-04-23T06:40:00Z",
  "in_reply_to": "<server.hello.id>",
  "payload": {
    "agent_version": "0.0.1",
    "hostname": "HP-Laptop",
    "platform": "win32",
    "os_release": "11"
  }
}
```

- `os_release` 는 `platform.release()` 결과 (선택 — 없어도 무방). 운영 관점 디버그용.
- 서버는 수신 시 `agents.last_seen_at = now()` 갱신. 이후 **프레임 수신 = 생존** 으로 취급.

핸드셰이크가 끝나면 M1.5 범위에선 별도 메시지를 주고받지 않는다. WS protocol-level ping/pong (ws 라이브러리·starlette 모두 자동) 이 연결 유지.

## 서버 설계

### 새 파일 `packages/backend/app/ws.py`

```python
@router.websocket("/v0/agent")
async def ws_agent(websocket: WebSocket) -> None:
    # 1) Authorization 헤더 검증 — accept 전에 close
    token = _extract_bearer_from_headers(websocket.headers)
    if token is None:
        await websocket.close(code=4401, reason="missing_token")
        return
    ...
    if agent.revoked_at is not None:
        await websocket.close(code=4403, reason="token_revoked")
        return

    await websocket.accept()

    # 2) server.hello 송신
    await websocket.send_json(_make_frame("server.hello", {
        "server_version": __version__,
        "agent_id": str(agent.id),
        "user_id": str(agent.user_id),
        "heartbeat_seconds": 20,
    }))

    # 3) agent.hello 수신 대기 (timeout 5s)
    try:
        first = await asyncio.wait_for(websocket.receive_json(), timeout=5.0)
    except (asyncio.TimeoutError, WebSocketDisconnect):
        await websocket.close(code=4400, reason="no_agent_hello")
        return

    if not _is_valid_hello(first):
        await websocket.close(code=4400, reason="invalid_hello")
        return

    # 4) last_seen_at 갱신
    agent.last_seen_at = datetime.now(timezone.utc)
    await session.commit()

    # 5) M1.5 는 여기까지. 연결 유지하며 클라이언트 종료 대기.
    try:
        while True:
            await websocket.receive_text()  # M2 에서 처리
    except WebSocketDisconnect:
        return
```

- FastAPI/Starlette 의 `WebSocket` 은 `accept` 전에 `close(code=...)` 호출 가능. 브라우저는 이 경우 "연결 실패" 이벤트를 받고 close code 는 못 본다는 이슈가 있지만, Python `websockets` 클라이언트는 handshake 이후 close code 를 제대로 수신한다. M1.5 스코프는 Python 클라이언트뿐이라 OK.
  - 실제로는 accept 전 close 시 HTTP 응답으로만 떨어져 클라이언트에 close code 가 전달 안 되는 스택이 많다. **안전 설계**: 인증 실패여도 `accept()` 먼저 한 뒤 바로 `close(code=4401)` 하자. 이렇게 하면 확실히 close code 가 전달된다.
- `session` 은 FastAPI Depends 로 주입 (기존 `get_session` 재사용).

### `app/main.py` — 라우터 추가

`from .routers import ws` 후 include.

### 인증 로직 분리

`app/dependencies.py` 에 이미 `current_agent` 가 있지만 REST 용이라 `Request` 를 받는다. WS 용으로는 `Headers` 객체와 `AsyncSession` 을 받는 헬퍼를 별도로 둔다:

```python
async def authenticate_agent_from_headers(
    headers, session: AsyncSession
) -> tuple[Agent | None, str | None]:
    """(agent, error_code) 반환. 성공 시 (Agent, None), 실패 시 (None, code)."""
```

`error_code` 는 close reason 으로 그대로 씀 (`missing_token`/`malformed_token`/`invalid_token`/`token_revoked`).

## Agent 설계

### 새 파일 `agent/ws_client.py`

의존성: `websockets>=12.0` (sync API 포함). 동기 API 를 사용해 기존 threaded 패턴과 정합 유지.

```python
class WebSocketClient:
    def __init__(
        self,
        server_url: str,
        auth_state: AuthState,
        on_unauthorized: Callable[[], None] | None = None,
    ) -> None: ...

    def start(self) -> None:
        """데몬 스레드에서 connect 루프 시작."""

    def stop(self) -> None:
        """현재 연결 종료 + 루프 종료 요청."""
```

내부:

- `_loop()` 이 `stop_event` 가 set 될 때까지 반복:
  - credentials 없으면 백오프 대기 (10s)
  - `connect(ws_url, additional_headers=[("Authorization", f"Bearer {token}")])`
  - `server.hello` 수신 → 버전 로그
  - `agent.hello` 송신
  - 수신 loop: 아무 프레임이나 받으면 로그. `ConnectionClosed` 시 break.
  - close code 4401/4403 → `on_unauthorized()` 호출 후 `stop_event.set()` (재연결 하지 않음 — 사용자 재로그인까지 대기)
  - 그 외 정상·비정상 종료 → 지수 백오프 (1s → 2s → 4s → ... → 60s cap) 후 재시도

백오프 초기값은 1 초, 연결 성공 시 리셋. `stop_event` 가 wait 를 깨움.

- `ws_url` 은 `server_url` 의 `http` → `ws` / `https` → `wss` 치환.

### `agent_main.py` 통합

```python
ws_client = WebSocketClient(
    server_url=server_url,
    auth_state=auth,
    on_unauthorized=lambda: auth.handle_unauthorized(icon),
)
ws_client.start()
...
finally:
    ws_client.stop()
    pinger.stop()
```

기존 `pinger` 구조와 대칭. AuthState 가 `handle_unauthorized` 에서 `ws_client` 를 **재연결 금지** 모드로 만드는 건 WS 내부 stop_event 로 충분 (서버가 4401 을 주면 stop_event 를 set). 재로그인 후에는 사용자가 Agent 를 재기동해야 WS 가 다시 붙는다 — M1.5 범위는 이 수준. M1.6 에서 "Sign In 성공 시 ws_client 를 restart" 로 연결하는 건 작은 follow-up.

`agent/requirements.txt` 에 `websockets>=12.0` 추가. PyInstaller bundle 에도 자동 포함 (pkgutil 기반 exfil).

## 검증 계획

### 로컬 (SQLite + uvicorn)

1. `uvicorn app.main:app --port 8765` 기동.
2. Python 인터랙티브 or 스크립트에서 `websockets.sync.client.connect("ws://127.0.0.1:8765/v0/agent", additional_headers=...)` 로 연결.
3. server.hello 수신 → payload 검증.
4. agent.hello 송신 → 서버 측 agents 테이블 last_seen_at 갱신 확인.
5. 잘못된 토큰 연결 → close code 4401 확인.
6. DB 에서 revoke 처리 후 재연결 → 4403 확인.
7. agent.hello 5초 내 미송신 → 4400 `no_agent_hello` 확인.

### 로컬 통합 (agent_main.py 직접 기동 대신 WebSocketClient 단독)

- `ws_client.start()` 호출, 3 초 기다림, 로그에 `server.hello received` + `agent.hello sent` + `last_seen_at updated` 확인.
- 서버 프로세스 kill → 자동 재연결 시도 로그 확인.
- DB revoke → 다음 재연결 시 4403 → `on_unauthorized` 발화 확인.

### Railway (wss)

1. 커밋 푸시 → 자동 배포 대기.
2. `wss://ohdo-production.up.railway.app/v0/agent` 로 연결 테스트.
3. 사용자 기기에서 agent 재기동 → agent.log 에 `WS connected`, `server.hello received`, `agent.hello sent` 3 줄 순차 확인.
