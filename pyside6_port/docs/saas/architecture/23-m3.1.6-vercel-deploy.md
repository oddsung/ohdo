## 목표

`packages/web` 을 Vercel 에 배포해 production URL 에서 사용자가 실제로 사용 가능하게. 이로써 M3.1.3·M3.1.4·M3.1.5 의 dev 격리 (web localhost ↔ backend Railway) 이슈가 자연 해소되고 브라우저 e2e 검증도 가능해진다.

M3.1.6 완료 조건:

- Vercel 에 `packages/web` 배포됨, production URL 발급.
- Vercel 환경변수 `API_BASE_URL` = Railway URL 등록.
- Railway 환경변수 `PUBLIC_BASE_URL` = Vercel URL 등록 → 매직링크가 Vercel 도메인으로 발송됨.
- (선택) Railway `OHDO_ENV=production` 추가 → secure cookie 활성화.
- 브라우저 e2e: 매직링크 sign-in → dashboard → 실 데이터 표시 → 신규 실행 / cancel / 캡처 그리드 모두 작동.
- 코어 회귀 25/25.

## 아키텍처 (배포 후)

```
[브라우저] ──https──→ ohdo-web-xxxxx.vercel.app
                          │
                          │ Next.js SSR (React server components)
                          │ Next.js rewrites (server-side proxy)
                          │
                          ├─/v0/*       ──https──→ ohdo-production.up.railway.app/v0/*
                          └─/auth/verify ──https──→ ohdo-production.up.railway.app/auth/verify

[브라우저 관점]: 모든 요청이 ohdo-web-xxxxx.vercel.app 에 가는 것처럼 보임 → same-origin
[쿠키]: ohdo_session 이 ohdo-web-xxxxx.vercel.app 도메인에 묶임 (HttpOnly, SameSite=Lax)
[매직링크 URL]: https://ohdo-web-xxxxx.vercel.app/auth/verify?token=...
                (Railway 의 PUBLIC_BASE_URL 이 Vercel URL 로 설정돼서)
```

### 왜 이 구조가 깨지지 않는가

- 브라우저가 보는 origin: 항상 Vercel URL 하나
- Cookie scope: Vercel URL 한 도메인
- API 호출도 Vercel URL 로 → rewrite 가 server-side 에서 Railway 로 proxy → 응답을 Vercel server 가 브라우저에 그대로 전달
- CORS 불필요 (모든 요청이 same-origin 으로 보임)
- 매직링크 URL 도 Vercel 도메인 → 클릭 시 same domain → 쿠키 설정도 같은 도메인

## 사용자 수동 단계

### A. Vercel 프로젝트 생성

1. https://vercel.com 접속 → 로그인 (GitHub 연동)
2. **Add New → Project**
3. **Import** → `oddsung/ohdo` 저장소 선택
4. **Configure Project**:
   - **Project Name**: `ohdo-web` (자유)
   - **Framework Preset**: `Next.js` (자동 감지)
   - **Root Directory**: `packages/web` ← **반드시 변경**
   - **Build Command**: `next build` (자동 채워짐)
   - **Output Directory**: `.next` (자동)
5. **Environment Variables**:
   - `API_BASE_URL` = `https://ohdo-production.up.railway.app`
6. **Deploy** 클릭
7. 배포 완료 후 발급된 URL 메모 (예: `https://ohdo-web-abc123.vercel.app`)

### B. Railway 환경변수 추가

1. https://railway.app 접속 → `ohdo-production` 프로젝트
2. **Variables** 탭
3. **+ New Variable**:
   - `PUBLIC_BASE_URL` = `https://ohdo-web-abc123.vercel.app` (위에서 받은 Vercel URL)
4. (선택, 권장) `OHDO_ENV` = `production` — secure cookie 활성화
5. 자동 재배포 대기 (~2분)

### C. 브라우저 검증

1. Vercel URL 접속 → `/sign-in` 으로 자동 redirect
2. 이메일 입력 → 매직링크 요청 → Railway 로그에서 verify URL 복사 (이번엔 Vercel 도메인으로 출력됨)
3. URL 클릭 → `/dashboard` 진입 → executions 리스트에 HP-Laptop agent 의 실 데이터 표시
4. 신규 실행 폼 → `print('hello from web')` → 즉시 실행되어 dashboard 에 추가됨
5. 진행 중인 실행 만들고 → 상세 페이지 → "취소" 버튼 → 1~2초 내 cancelled
6. 실패 스텝 만들고 → 캡처 그리드에 인라인 PNG 표시
7. 로그아웃 → 쿠키 제거 → /sign-in 으로 복귀

## 알려진 한계 (M3.1.6+ 보강)

1. **Rate limiting 없음** — 매직링크 무한 발송 방지 필요. Stripe/요금제 도입 (M3.2) 시 같이.
2. **CORS 불필요 (현재)** — 만약 third-party 도메인에서 직접 API 호출 받게 되면 CORS 추가 필요.
3. **커스텀 도메인** — `app.ohdo.ai` 매핑은 Vercel 대시보드에서 가능 (도메인 등록 후). 현재 범위 밖.
4. **이메일 SMTP 미연결** — 매직링크가 아직 서버 로그 stub. 실 발송은 M3.2.
5. **Vercel free tier 제약** — function 10s timeout. 우리 polling/upload 는 모두 그 안.
