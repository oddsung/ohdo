# 08. M2.1 — `executions` 테이블 + 마이그레이션 `0003`

- **상태**: 구현 착수 (2026-04-23)
- **이전 단계**: [07-m1.5-websocket-hello.md](07-m1.5-websocket-hello.md) — WS 핸드셰이크
- **다음 단계**: M2.2 — REST `POST /v0/executions` (세션 JSON 수신·저장)

## 목표

M2 (실제 RPA 실행 연결) 의 **가장 얇은 서버측 스키마만** 추가한다. API·에이전트·WS 는 **건드리지 않는다**. 다음 단계(M2.2) 에서 이 테이블을 바탕으로 REST 를 올린다.

M2.1 완료 조건:

- 새 테이블 `executions` 가 로컬 SQLite + Railway Postgres 양쪽에 존재.
- `Execution` SQLAlchemy 모델이 `target_metadata` 에 등록되어 Alembic autogenerate 대상.
- 기존 API/라우터/WS 동작 무변경 (회귀 없음). 코어 테스트 25/25.
- 마이그레이션 `0003` 은 `0002 → 0003` 으로 체인, `downgrade()` 도 구현.

## 왜 이 스키마가 필요한가

[프로토콜 v0 §3.2](../protocols/AGENT_PROTOCOL.md#32-예시--executionstart) 의 `execution.start` / `execution.result` 는 다음 식별자·상태를 공유한다:

- `execution_id` — 하나의 실행을 대표하는 불변 ID (서버 발급).
- `session_id` — 실행할 세션 JSON (로컬 Agent 가 가진 스텝 리스트).
- `agent_id` — 어느 기기에서 돌릴지.
- 상태 전이: `queued → accepted → running → completed | failed | cancelled`.

이걸 백엔드에서 **영속화** 하지 않으면:

- 네트워크 단절 시 "방금 지시한 실행이 뭐였는지" 복구 불가.
- 여러 에이전트·여러 탭에서 동시에 본 화면 간 동기화 불가.
- `last_event_id` 기반 재전송 (`AGENT_PROTOCOL §5`) 구현 여지 봉쇄.

M2.1 은 이 테이블만 추가. 실제 채우는 로직은 M2.2+.

## 테이블 설계

### `executions`

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| `id` | `Uuid` | PK, default uuid4 | 내부 PK |
| `execution_id` | `Text` | **unique**, indexed | API 에 노출될 public id (`exec_` prefix ULID/uuid). M2.2 에서 발급 로직 추가. |
| `agent_id` | `Uuid` | FK → `agents.id` ON DELETE CASCADE, indexed | 이 실행이 바운드된 기기 |
| `user_id` | `Uuid` | FK → `users.id` ON DELETE CASCADE, indexed | 이 실행을 소유한 사용자. 에이전트 삭제 후에도 리텐션 정책 반영 쉽게. |
| `status` | `Text` | not null, default `'queued'`, indexed | `queued` / `accepted` / `running` / `completed` / `failed` / `cancelled` |
| `session_snapshot` | `JSON` | nullable | `Session` dataclass → dict 직렬화 결과 전체 복사. 에이전트 측 편집으로부터 격리. M2.2 에서 채움. |
| `from_step` | `Integer` | nullable | 부분 재실행 시 시작 스텝 (1-based). null 이면 처음부터. |
| `to_step` | `Integer` | nullable | null 이면 마지막까지. |
| `total_steps` | `Integer` | nullable | 결과 집계 (`ExecutionReport.total_steps`). |
| `executed_steps` | `Integer` | nullable | |
| `successful_steps` | `Integer` | nullable | |
| `failed_steps` | `Integer` | nullable | |
| `total_time_ms` | `Integer` | nullable | |
| `error_summary` | `Text` | nullable | 실패 요약 (e.g. `"step 3: ElementNotFound"`). 전체 traceback 은 별도 로그 스트림 저장소로 미룸 (M2.4). |
| `started_at` | `DateTime(tz)` | nullable | 에이전트가 `execution.accepted` 보낸 시각 |
| `finished_at` | `DateTime(tz)` | nullable | 최종 상태 도달 시각 |
| `created_at` | `DateTime(tz)` | not null, server default now() | Mixin |
| `updated_at` | `DateTime(tz)` | not null, server default now(), onupdate now() | Mixin |

### 인덱스

- `executions_execution_id_idx` — unique. API 조회 hot path.
- `executions_agent_id_idx` — "이 기기의 최근 실행" 질의.
- `executions_user_id_idx` — "내 실행 전체" 질의.
- `executions_status_idx` — 큐 상태별 필터 (예: `queued` 만).

복합 인덱스는 M2.2 의 조회 패턴을 본 뒤 추가. M2.1 에서는 과잉.

### JSON 타입 선택

- SQLAlchemy `sa.JSON` (type-generic) 사용. Postgres 는 `JSONB` 로, SQLite 는 TEXT 로 매핑되어 양쪽 모두 통과.
- `JSONB` 로 강제하지 않는 이유: 로컬 e2e 를 SQLite 로 계속 돌리는 M1 패턴 유지.

### 상태 머신 (M2 전체 걸쳐)

```
queued ──┐
         ▼
     accepted ──► running ──► completed
                        │
                        ├──► failed
                        │
                        └──► cancelled
```

M2.1 은 값만 허용. 전이 규칙 강제 로직은 M2.3 (WS `execution.*` 처리) 에서 추가.

## 구현

### `app/models/execution.py` (신규)

```python
"""Execution 모델 — 에이전트에서 RPA 세션을 실행한 단위."""

from __future__ import annotations

import uuid
from datetime import datetime

from sqlalchemy import (
    JSON, DateTime, ForeignKey, Index, Integer, Text, Uuid,
)
from sqlalchemy.orm import Mapped, mapped_column

from .base import Base, TimestampMixin


class Execution(Base, TimestampMixin):
    __tablename__ = "executions"
    __table_args__ = (
        Index("executions_execution_id_idx", "execution_id", unique=True),
        Index("executions_agent_id_idx", "agent_id"),
        Index("executions_user_id_idx", "user_id"),
        Index("executions_status_idx", "status"),
    )

    id: Mapped[uuid.UUID] = mapped_column(Uuid, primary_key=True, default=uuid.uuid4)
    execution_id: Mapped[str] = mapped_column(Text, nullable=False, unique=True)
    agent_id: Mapped[uuid.UUID] = mapped_column(
        Uuid, ForeignKey("agents.id", ondelete="CASCADE"), nullable=False
    )
    user_id: Mapped[uuid.UUID] = mapped_column(
        Uuid, ForeignKey("users.id", ondelete="CASCADE"), nullable=False
    )
    status: Mapped[str] = mapped_column(
        Text, nullable=False, default="queued", server_default="queued"
    )
    session_snapshot: Mapped[dict | None] = mapped_column(JSON, nullable=True)
    from_step: Mapped[int | None] = mapped_column(Integer, nullable=True)
    to_step: Mapped[int | None] = mapped_column(Integer, nullable=True)
    total_steps: Mapped[int | None] = mapped_column(Integer, nullable=True)
    executed_steps: Mapped[int | None] = mapped_column(Integer, nullable=True)
    successful_steps: Mapped[int | None] = mapped_column(Integer, nullable=True)
    failed_steps: Mapped[int | None] = mapped_column(Integer, nullable=True)
    total_time_ms: Mapped[int | None] = mapped_column(Integer, nullable=True)
    error_summary: Mapped[str | None] = mapped_column(Text, nullable=True)
    started_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True), nullable=True)
    finished_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True), nullable=True)
```

`app/models/__init__.py` 에 `Execution` 등록 필수 (Alembic autogenerate 가 Base.metadata 를 통해 보도록).

### Alembic `0003` (수동 작성, `0002` 스타일 답습)

- `op.create_table("executions", ...)` + FK + 인덱스 4개.
- `downgrade()`: 인덱스 역순 drop → table drop.

### 스키마 이외의 변경 없음

- 라우터·dependency·WS 모두 무변경.
- `app/main.py` 변경 없음 (라우터 추가 아님).

## 검증

### 로컬 (SQLite)

1. `alembic upgrade head` → `executions` 생성 확인 (`sqlite3 .schema executions`).
2. `alembic downgrade -1` → 테이블 drop 확인.
3. 다시 `upgrade head`.
4. Python 에서 `Execution` 샘플 insert → query → 확인.
5. `python -m tests.test_runner --suite core` → 25/25.

### Railway (Postgres)

- `git push` 후 자동 배포.
- `startCommand` 의 `alembic upgrade head` 가 `0003` 적용.
- `/healthz` 200 + Railway 로그에 `0003` 적용 메시지 확인.
- (선택) `psql` 로 `\d executions` 확인.

## 범위 밖

- API 라우터 (`POST /v0/executions` 등) → M2.2
- WS `execution.start` / `.progress` / `.result` → M2.3
