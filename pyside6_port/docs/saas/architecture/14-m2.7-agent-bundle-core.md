# 14. M2.7 — Agent PyInstaller 번들에 `core/` 포함 + Inno Setup 재빌드

- **상태**: 구현 착수 (2026-04-24)
- **이전 단계**: [13-m2.6-captures-upload.md](13-m2.6-captures-upload.md)
- **M2 마지막 서브마일스톤**

## 목표

M2.3 에서 `agent/runner.py` 가 `core.workflow_engine` 을 import 하도록 했지만, 이는 로컬 개발 런 (`python -m agent.agent_main` with sys.path fallback) 에서만 작동했다. PyInstaller 번들 (`ohdo-agent.exe`) 에는 `core/` 가 포함되지 않아 설치본으로 실행 시 `ImportError: No module named core`.

M2.7 에서는 **번들에 `core.workflow_engine` 을 주입** 하여 설치된 Agent 가 M2.3~M2.6 의 전 플로우를 그대로 사용할 수 있게 만든다.

M2.7 완료 조건:

- `build.spec` 수정: `pathex` 에 프로젝트 루트 추가 + `core.workflow_engine` 을 hiddenimports 에 명시.
- runner 가 사용하지 않는 core 모듈 (UI/AI/세션 관리 등) 은 `excludes` 로 명시해 트랜지티브 의존성 (PyQt6, selenium 등) 이 딸려오는 것 방지.
- `pyinstaller build.spec --clean --noconfirm` 성공.
- 결과 `dist/ohdo-agent/` 의 총 용량이 이전 대비 **+5 MB 이하** (core.workflow_engine 자체는 28 KB, stdlib 만 사용하므로 증가 최소).
- 번들 exe 기동 시 `ImportError` 발생 여부 확인.
- (선택) Inno Setup 재빌드 → `dist-installer/ohdo-agent-setup-*.exe` 갱신.
- CHANGELOG + memory 업데이트.
- 설치본 실기 검증 (end-to-end device flow + POST execution + cancel + capture) 은 **사용자가 별도 시점에 수행**.

## build.spec 변경점

### pathex

```python
PROJECT_ROOT = AGENT_ROOT.parent  # ohdo/
pathex=[str(AGENT_ROOT), str(PROJECT_ROOT)]
```

PyInstaller 의 모듈 탐색 경로. `agent_main.py → runner.py → from core.workflow_engine import ...` 가 해석되게.

### hiddenimports

`runner.py` 의 core import 는 try/except 블록 안이라 PyInstaller static analyzer 가 놓칠 수 있다. 명시.

```python
hiddenimports=[
    "pystray._win32",
    "PIL.Image",
    "PIL.ImageDraw",
    "core",
    "core.workflow_engine",
]
```

### excludes — core 의 나머지

runner 는 `core.workflow_engine` 하나만 사용. 다른 core 모듈은 PyQt6·selenium·pywinauto 등 무거운 의존성을 끌고 오므로 **명시적 제외**:

```python
excludes=[
    ...existing...,
    "core.adapters", "core.adapters.base_adapter", "core.adapters.gemini_cli_adapter",
    "core.ai_engine",
    "core.app_service",
    "core.environment_scanner",
    "core.execution_kernel",
    "core.import_manager",
    "core.kernel_worker",
    "core.prompt_builder",
    "core.session_manager",
    "core.storage",
    "core.visual_overlay",
    "core.win_inspector",
]
```

### `core/workflow_engine.py` 내부의 지연 import

- `_capture_error_screen` → `import mss; from PIL import Image` 지연 로드. mss 가 agent venv 에 없어도 번들 시 영향 없음 (hiddenimports 아닌 런타임 lazy).
- `_start_overlay` → `_OVERLAY_SCRIPT` 경로 확인. runner 가 `visual_feedback_enabled=False` 로 생성하므로 호출되지 않음.
- `CodeSandbox.execute` → `subprocess.Popen(python_exe, ...)` 로 별도 프로세스에서 user code 실행. **번들된 python.exe** 가 아닌 시스템 Python 이 있어야 함 → `sys.executable` 이 ohdo-agent.exe 가 되는 문제 존재 (아래 "알려진 제약" 참조).

## 알려진 제약 (M2.7 범위 밖)

### 1. user code 실행용 Python 인터프리터

`CodeSandbox.__init__` 은 `python_exe = python_exe or sys.executable` 을 쓴다. 번들 실행 시 `sys.executable == ohdo-agent.exe`. subprocess 로 이걸 호출하면 **Agent 자체가 재귀적으로 실행**됨 (PyInstaller 의 bootstrapper).

**임시 회피 (이번 세션 밖)**: M2.8 혹은 별도 개선에서
- 설치본에 python 서브인터프리터 (embedded python) 를 동반 설치
- 혹은 시스템 Python 탐지 (py launcher, PATH) 폴백
- 혹은 핵심 subprocess 용 mini-exe 번들

M2.7 범위: **이 제약을 명시적으로 문서화만 하고 수정은 미룸**. 현 설치본으로 실제 RPA 코드를 돌리면 실패할 수 있음 — device flow / WS 핸드셰이크 / 로그 / 캡처 upload 자체 플로우는 돈다.

### 2. core/visual_overlay.py

번들에 포함 안 됨 (excludes). runner 가 `visual_feedback_enabled=False` 로 엔진 생성하므로 안전.

### 3. mss 미포함

agent/requirements.txt 에 `mss` 없음. `screenshot_on_error=True` 지만 `_capture_error_screen` 내부 try/except 로 None 반환 + warn. M2.6 의 monkey-patch 테스트가 동작 검증한 대로 **real mss 없이도 업로드 파이프라인 자체는 작동**하지만 실제 스크린샷 저장은 못 함.

실운영 개선: `mss` 를 agent/requirements.txt 에 추가 + build.spec 에 hiddenimport. **M2.7 범위 밖**.

## 버전

M2.7 완료 시점에 Agent 버전을 `0.0.1 → 0.1.0` 으로 bump (M2 전체 묶음). 파일 3개 동기화:

## 검증

### 빌드

```
cd agent/
pyinstaller build.spec --clean --noconfirm
```

성공 조건:
- 빌드 오류 없음
- `dist/ohdo-agent/_internal/` 안에 `core/workflow_engine.pyc` (혹은 PYZ 내부) 존재

### Smoke test (번들 exe 기동)

```
.\dist\ohdo-agent\ohdo-agent.exe
```

몇 초 관찰:
- 트레이 아이콘 표시 여부
- `%APPDATA%\ohdo\agent.log` 에 기동 라인 + 기존 healthz ping 라인

실패하면 로그의 traceback 확인. `ImportError: core.workflow_engine` 이면 spec 수정 필요.

### Inno Setup 재빌드 (선택)

로컬에 `ISCC.exe` 가 있으면:
```
& "C:\Program Files (x86)\Inno Setup 6\ISCC.exe" installer\ohdo-agent.iss
```

없으면 사용자가 별도 수행. README 에 명령어 기록.

## Core 수정

**없음**. 기존 `core/workflow_engine.py` 는 그대로. build.spec 만 수정.
