# 16. M2.9 — Embedded Python 에 pip + 핵심 RPA 패키지 번들

- **상태**: 구현 착수 (2026-04-24)
- **이전 단계**: [15-m2.8-embedded-python.md](15-m2.8-embedded-python.md)
- **다음 단계**: M2.10 — session_snapshot `requirements` 필드 + 런타임 auto-install (선택)

## 목표

M2.8 에서 embedded Python 3.12 을 번들에 동반해 **코드 실행은 가능** 해졌지만 stdlib 만 있음. 사용자 RPA 코드가 `import pywinauto` / `selenium` / `pyautogui` 쓰면 ImportError. M2.9 는 **기본 RPA 시나리오를 설치본에서 바로 가능** 하게 만든다.

M2.9 완료 조건:

- 빌드 시점에 embedded python 에 pip 가 설치되어 있음.
- 빌드 시점에 `pywinauto`, `pyautogui`, `selenium`, `mss` 4개 패키지가 pre-install 되어 있음.
- `._pth` 파일에 `import site` 활성화 → site-packages 검색 가능.
- 설치본의 `_internal/python/python.exe` 에서 4개 패키지 import 성공.
- CodeSandbox 가 이 python 을 subprocess 로 실행할 때 user code 가 위 패키지를 쓸 수 있음.
- 코어 회귀 25/25.
- 사용자 추가 패키지는 M2.9 에선 사용자가 `subprocess` 로 `pip install` 호출해 설치 가능 (session_snapshot 의 requirements 필드 자동화는 M2.10+).

### `mss` 추가 이유

M2.6 에서 `screenshot_on_error=True` 로 돌아갔지만 `mss` 가 없어 실제 캡처는 None 반환 + warn 로그. 이번에 포함하면:
- CodeSandbox 실패 스텝의 실제 화면 스크린샷이 `result.error_screenshot` 에 채워짐
- runner 가 이를 `POST /v0/executions/{id}/captures` 로 업로드
- M2.6 "monkey-patch 로만 검증" 제약도 자연스럽게 해소

## 구현

### `scripts/fetch-embedded-python.ps1` 업데이트

기존 3단계 (download / extract / print version) 뒤에 3단계 추가:

1. `._pth` 편집: `#import site` → `import site` 로 (regex)
2. `get-pip.py` 다운로드 → `python.exe get-pip.py` 실행 → pip 설치
3. `pip install pywinauto pyautogui selenium mss` 수행

idempotency:
- python.exe 존재 + `Lib/site-packages/pip/` 존재 + 4 패키지 마커 폴더 존재 → skip
- 일부만 있으면 부분 설치 (pip install 은 이미 설치된 건 skip)

### 예상 용량 변화

| 단계 | 크기 |
|---|---|
| vendor/python (M2.8, stdlib only) | 22 MB |

## 검증

### 빌드

```
powershell -File agent/scripts/fetch-embedded-python.ps1
# → 한 번에 다운 + 추출 + pip + 4 패키지 설치
# → 마지막에 "import pywinauto, pyautogui, selenium, mss; OK" 찍힘
```

### CodeSandbox 단위 검증 (bundle 내 python 으로)

```python
from core.workflow_engine import CodeSandbox
sb = CodeSandbox(python_exe="dist/ohdo-agent/_internal/python/python.exe", timeout=10)

r = sb.execute("import pywinauto; print('pywinauto:', pywinauto.__version__)")
assert r.success

r = sb.execute("import pyautogui; print('pyautogui:', pyautogui.__version__, 'size:', pyautogui.size())")
assert r.success  # pyautogui.size() 는 실제 화면 해상도 반환

r = sb.execute("from selenium import webdriver; print('selenium ok')")
assert r.success

r = sb.execute("import mss; sct = mss.mss(); print('monitors:', len(sct.monitors))")
assert r.success
```

### 설치본 실기 (사용자 재검증)

M2.8 에서 이미 확인된 cancel 플로우는 여전히 작동해야 함 (regression 방지). 추가로:

```powershell
$BODY = @{
  session_snapshot = @{
    session_id = "m29-test"
    steps = @(@{ step_id=1; generated_code="import pyautogui; w,h = pyautogui.size(); print(f'screen {w}x{h}')" })
  }
} | ConvertTo-Json -Depth 5
# POST → status=completed + stdout 에 "screen 1920x1080" 등
```

## 알려진 제약 (M2.10+)

1. **패키지 목록 고정** — 빌드 시점 확정. 사용자가 dict 로 requirements 명시해 자동 설치는 M2.10.
2. **런타임 pip 설치는 가능하지만 install 위치 이슈** — embedded python 에 `--user` 는 site 가 없어서 못 씀. 사용자는 `--target=<dir>` 로 설치한 뒤 sys.path 추가 필요. M2.10 에서 런처 helper 로 간소화.
3. **Chrome/Edge WebDriver 바이너리 미포함** — selenium 은 들어있지만 브라우저 드라이버는 OS 에 의존. `webdriver-manager` 를 포함할지 M2.10 검토.
4. **번들 용량** — 설치본 50 MB 근처. Pro 툴 기준 문제없으나 onefile 모드 검토 여지.
